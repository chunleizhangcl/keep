告警去重是 Keep 的关键能力，用于通过将相似告警归并来降低噪音并简化事件管理。该过程确保团队不会被大量重复通知淹没，从而更高效、更专注地响应事件。

## 术语表

- **去重规则**：用于判断告警是否应归并的一组条件。
- **部分去重**：将同一告警的不同实例关联为一条告警，考虑同一告警但状态不同（例如 firing 与 resolved）的情况。这是默认模式，使用指定字段识别并归并相关告警。
- **指纹字段**：用于识别相似告警的特定告警属性。
- **完全去重**：当除忽略字段外全部字段完全一致时，认为告警相同并丢弃重复告警，以避免系统负载过高。
- **忽略字段**：在完全去重模式下，用于比较时排除的字段。

## 去重类型

### 部分去重

部分去重允许你指定某些字段（指纹字段）来识别相似告警。具有这些字段相同值的告警会被视为重复并归并。该方式灵活，可精细控制去重策略。

Keep 集成的每个 provider 都带有针对其告警格式和常见用例预置的部分去重规则。
默认指纹字段通过 provider 代码中的 `FINGERPRINT_FIELDS` 属性定义（如 [datadog provider](https://github.com/keephq/keep/blob/main/keep/providers/datadog_provider/datadog_provider.py#L188) 或 [gcp monitoring provider](https://github.com/keephq/keep/blob/main/keep/providers/gcpmonitoring_provider/gcpmonitoring_provider.py#L52)）。

### 完全去重

启用完全去重后，Keep 会丢弃完全相同的事件（忽略字段除外）。该模式会比较告警的所有字段（排除显式忽略字段），以判断是否为重复告警。

默认情况下，除 `lastReceived` 外完全一致的事件会被完全去重并丢弃，从而避免系统因重复告警而过载。

## 告警与结果示例

### 示例 1：部分去重

**规则** - 基于 `service` 与 `error_message` 字段去重。

```json
# alert 1
{
    "service": "payment",
    "error_message": "Database connection failed",
    "severity": "high",
    "lastReceived": "2023-05-01T10:00:00Z"
}
# alert 2
{
    "service": "payment",
    "error_message": "Database connection failed",
    "severity": "critical",
    "lastReceived": "2023-05-01T10:05:00Z"
}
# alert 3
{
    "service": "auth",
    "error_message": "Invalid token",
    "severity": "medium",
    "lastReceived": "2023-05-01T10:10:00Z"
}
```

**结果**：
- 告警 1 与 2 被去重为一条告警，字段会更新。
- 告警 3 由于 service 与 error_message 不同而保持独立。

### 示例 2：完全去重

**规则**：完全去重，并将 `timestamp` 设为忽略字段

**输入告警**：

```json

# alert 1
{
    service: "api",
    error: "Rate limit exceeded",
    user_id: "12345",
    lastReceived: "2023-05-02T14:00:00Z"
}
# alert 2（因为完全一致而被丢弃）
{
    service: "api",
    error: "Rate limit exceeded",
    user_id: "12345",
    lastReceived: "2023-05-02T14:01:00Z"
}
# alert 3
{
    service: "api",
    error: "Rate limit exceeded",
    user_id: "67890",
    lastReceived: "2023-05-02T14:02:00Z"
}
```

**结果**：
- 告警 1 与 2 在忽略 timestamp 后完全一致，因此被去重。
- 告警 3 因 user_id 不同而保持独立。

## 工作原理

Keep 的去重流程包括以下步骤：

1. **告警接入**：Keep 首先接收并接入每条告警。

2. **富化**：接入后，告警会经过富化流程，补充额外上下文信息。

3. **去重**：富化完成后，告警去重器开始工作，对富化后的告警应用去重规则。

### 去重是否使用 provider 指纹？

是的。`AlertDeduplicator` 会先按**指纹**分组，再按内容哈希判断：

- **指纹**（来自 provider 或自定义规则）决定告警是否属于同一组。
- **内容哈希**（对移除忽略字段后的告警 payload 做 SHA-256）决定是**完全重复**还是**部分重复**。

这意味着 **指纹不同的告警永远不会互相比较**；只有具有相同指纹的告警才会进行去重判断。

### 去重算法（实现层面）

`keep/api/alert_deduplicator/alert_deduplicator.py` 的逻辑对每条进入的告警执行如下步骤：

1. **克隆告警**，避免修改原始告警。
2. **移除忽略字段**（例如 `lastReceived`）。
3. **计算告警哈希** = `sha256(json.dumps(alert_copy, sort_keys=True).encode())`。
4. **读取该指纹的上一条哈希**。
5. **比较**：
   - 若存在上一条哈希且相同 → **完全重复**（`isFullDuplicate = True`）。
   - 若存在上一条哈希但不同 → **部分重复**（`isPartialDuplicate = True`）。
   - 若无上一条哈希 → **非重复**。

```text
进入的告警
   │
   ├─ fingerprint（来自 provider/自定义规则）
   │
   ├─ alert_copy = deepcopy(alert)
   ├─ 从 alert_copy 移除 ignore_fields
   ├─ alert_hash = sha256(json.dumps(alert_copy, sort_keys=True).encode())
   │
   ├─ last_hash = get_last_alert_hashes_by_fingerprints(fingerprint)
   │
   ├─ if last_hash == alert_hash:
   │       isFullDuplicate = True
   ├─ elif last_hash exists:
   │       isPartialDuplicate = True
   └─ else:
           非重复
```

### 去重算法能否剥离？

可以。该算法是自包含的，只要提供以下能力即可复用：

- **指纹函数**（例如基于指定字段生成指纹）。
- **按指纹存取上一条哈希**的存储方式（DB、Redis、缓存等）。
- **忽略字段列表**，用于完全去重对比。

最小可复用结构：

```python
import json
from copy import deepcopy
from hashlib import sha256
from typing import Callable

# remove_field 应删除 alert_copy 中形如 "labels.instance" 的嵌套键
#（例如在确认 "labels" 存在后执行 del alert_copy["labels"]["instance"]）。
# 需在你的项目中实现；Keep 的实现位于 AlertDeduplicator._remove_field，
# 当父级键不存在时应跳过删除（缺失不报错）。
def deduplicate(
    alert: dict,
    fingerprint: str,
    ignore_fields: list[str],
    last_hash_by_fingerprint: dict[str, str],
    remove_field: Callable[[dict, str], None],
):
    """返回 (dedup_type, alert_hash)。

    参数:
        alert: 需要检查的告警对象/字典。
        fingerprint: 用于分组的指纹字符串。
        ignore_fields: 计算哈希时需要排除的字段路径列表。
        last_hash_by_fingerprint: 指纹 -> 上一次哈希的映射。
        remove_field: Callable[[dict, str], None]，用于从 alert_copy 删除嵌套键，
            使用类似 "labels.instance" 的点分路径。

    返回:
        tuple[str, str]: (dedup_type, alert_hash)，dedup_type 取值为
        "full"、"partial" 或 "none"。
    """
    alert_copy = deepcopy(alert)
    for field in ignore_fields:
        remove_field(alert_copy, field)
    # encode() 默认使用 UTF-8，确保哈希一致性
    alert_hash = sha256(json.dumps(alert_copy, sort_keys=True).encode()).hexdigest()
    last_hash = last_hash_by_fingerprint.get(fingerprint)
    if last_hash == alert_hash:
        return "full", alert_hash
    if last_hash:
        return "partial", alert_hash
    return "none", alert_hash
```

在其他系统中可以按照如下步骤使用：

1. 为事件计算 `fingerprint`。
2. 获取该指纹的上一条哈希。
3. 执行上述算法。
4. 将当前哈希保存为该指纹的最新哈希。
