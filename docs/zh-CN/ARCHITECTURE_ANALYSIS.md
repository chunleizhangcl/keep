## 1. Keep 框架概述

### 1.1 什么是 Keep？

Keep 是一个**开源的 AIOps 和告警管理平台**，提供以下核心能力：

- 🔍 **统一视图**: 为所有告警和事件提供可定制的UI界面
- 🛠️ **告警处理瑞士军刀**: 去重、关联、过滤和富化
- 🔄 **深度集成**: 与100+监控工具的双向同步
- ⚡ **自动化**: 类似 GitHub Actions 的工作流引擎
- 🤖 **AIOps 2.0**: AI驱动的关联和总结

### 1.2 主要特性

- **单一管理平台**: 集中管理来自多个数据源的告警
- **智能去重**: 自动识别和合并重复告警
- **告警富化**: 通过机器学习和规则引擎增强告警信息
- **事件关联**: 自动将相关告警分组为事件
- **工作流自动化**: 根据告警触发自动化响应

## 3. 数据来源对接模块（Providers）

### 3.1 Providers 模块架构

**Providers** 是 Keep 框架中最关键的模块之一，负责与100多个外部数据源进行集成。这是一个高度可扩展的插件式架构。

#### 3.1.1 核心设计模式

```
┌─────────────────────────────────────────────────────────────┐
│              ProvidersFactory (工厂模式)                     │
│  - 动态加载和实例化提供商                                    │
│  - 反射机制发现所有提供商                                    │
│  - 管理提供商配置和密钥                                      │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────────┐
│              BaseProvider (抽象基类)                         │
│  - 提供标准接口                                              │
│  - 配置管理 (ProviderConfig)                                │
│  - 认证和密钥管理                                            │
│  - Webhook 模板                                             │
│  - 告警指纹字段 (FINGERPRINT_FIELDS)                        │
└────────────────┬────────────────────────────────────────────┘
                 │
                 ├─── BaseTopologyProvider (拓扑发现)
                 ├─── BaseIncidentProvider (事件管理)
                 └─── BaseProvider (标准提供商)
                        │
                        ├── DatadogProvider
                        ├── PrometheusProvider
                        ├── SlackProvider
                        ├── PagerDutyProvider
                        └── ... (100+ 提供商)
```

### 3.2 提供商类型

Keep 支持三大类提供商：

#### 类型 1: 标准提供商 (BaseProvider)
- **用途**: 发送通知、查询数据
- **能力**:
  - `_notify()`: 发送告警通知
  - `_query()`: 查询监控数据
  - `setup_webhook()`: 配置 webhook
  - `_get_alerts()`: 拉取告警

#### 类型 2: 拓扑提供商 (BaseTopologyProvider)
- **用途**: 系统拓扑和服务依赖发现
- **示例**: Kubernetes、AWS、GCP

#### 类型 3: 事件管理提供商 (BaseIncidentProvider)
- **用途**: 事件管理系统集成
- **示例**: PagerDuty、OpsGenie、Incident.io

### 3.3 提供商目录结构

每个提供商都遵循统一的目录结构：

### 4.2 去重机制详解

去重是 Keep 最重要的功能之一，采用**两级去重策略**：

#### 4.2.1 指纹计算 (Fingerprint)

```python
# 指纹字段选择策略:
1. 自定义去重规则 (fingerprint_fields)
2. 提供商默认字段 (FINGERPRINT_FIELDS)
3. 全局默认字段: ["name", "service", "source"]

# 指纹计算
fingerprint = sha256(
    sorted_fields_json
).hexdigest()
```

#### 4.2.2 哈希比对 (Alert Hash)

```python
# 应用忽略字段后计算哈希
alert_copy = remove_ignored_fields(alert, rule.ignore_fields)
alert_hash = sha256(
    json.dumps(alert_copy.dict(), sort_keys=True)
).hexdigest()

# 比对逻辑
if alert_hash == last_alert_hash:
    alert.isFullDuplicate = True  # 完全重复
elif last_alert_exists:
    alert.isPartialDuplicate = True  # 部分重复
```

### 4.3 告警富化过程

富化通过 **EnrichmentsBL** 模块实现，支持多种方式：

1. **预定义规则富化**
   - 基于 SQL 查询添加字段
   - 基于外部 API 调用
   - 基于历史数据统计

2. **AI 富化 (LLM)**
   - 使用 OpenAI/Anthropic/Ollama 等
   - 自动生成告警摘要
   - 智能推荐处理步骤

3. **拓扑富化**
   - 添加服务依赖关系
   - 关联受影响的服务

4. **历史上下文**
   - 计算触发次数 (firing_counter)
   - 计算持续时间 (firing_time)
   - 添加上次解决时间

### 4.4 事件关联引擎

**RulesEngine** 使用 CEL (Common Expression Language) 进行告警关联：

```yaml
# 示例规则
- name: "Database高CPU事件"
  condition: |
    alert.severity == "critical" && 
    alert.service.startswith("db-") &&
    alert.name == "HighCPU"
  group_by:
    - service
    - datacenter
  create_incident:
    title: "数据库 {{ alert.service }} 高CPU"
    severity: "high"
```

执行流程：
1. 评估所有规则的条件
2. 匹配的告警按 `group_by` 分组
3. 自动创建或更新事件 (Incident)
4. 将告警关联到事件

## 6. 关键技术点总结

### 6.1 架构模式
- **微服务架构**: API 和 Worker 分离
- **异步处理**: ARQ (基于 Redis) 进行后台任务处理
- **插件化**: Providers 采用工厂模式和反射机制
- **多租户**: 完整的租户隔离支持

### 6.2 可扩展性
- **水平扩展**: API 服务器和 Worker 可独立扩展
- **队列缓冲**: Redis 队列缓冲高峰流量
- **数据库优化**: 索引、分区、缓存

### 6.3 可靠性
- **重试机制**: ARQ 任务失败重试
- **审计日志**: 完整的操作审计
- **指标监控**: Prometheus + OpenTelemetry

### 6.4 安全性
- **多种认证**: OAuth2, API Key, JWT
- **RBAC**: 细粒度权限控制
- **密钥管理**: 支持多种密钥管理后端
- **租户隔离**: 数据完全隔离

## 7. 总结

### 7.1 核心优势

1. **统一平台**: 通过 100+ 提供商集成，实现告警的统一管理
2. **智能处理**: AI 驱动的去重、关联和富化
3. **高度可扩展**: 插件式架构，易于添加新的数据源
4. **自动化能力**: 强大的工作流引擎和规则引擎
5. **企业级功能**: 多租户、RBAC、审计、可观测性

### 7.2 适用场景

- 多数据源告警统一管理
- 告警降噪和智能过滤
- 事件驱动的自动化运维
- SRE 和 DevOps 团队协作
- AIOps 平台建设

### 7.3 技术栈

**后端**:
- Python 3.11+
- FastAPI (API 框架)
- SQLAlchemy (ORM)
- ARQ (异步任务队列)
- CEL (规则引擎)

**前端**:
- Next.js (React)
- TypeScript
- Tailwind CSS

**数据存储**:
- PostgreSQL / MySQL (主数据库)
- Redis (队列和缓存)
- ElasticSearch (可选，搜索)

**基础设施**:
- Docker / Kubernetes
- Prometheus (监控)
- OpenTelemetry (追踪)
